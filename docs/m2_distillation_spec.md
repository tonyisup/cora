# Milestone 2 — Distillation Spec

**Status:** Draft
**Date:** 2026-05-21

## Goal

Distill the M1 speaking policy into a smaller, faster learned model that:
1. Matches the deterministic baseline on the 5 "easy" turn-taking scenarios
2. Generalizes better than the baseline on ambiguous / hard-negative cases
3. Runs with low enough latency for near-real-time use (~100–200ms per decision)

The LLM is the teacher. The deterministic policy is the safety rail. The distilled model is the product.

---

## Teacher Selection

From the 15-model benchmark (few-shot results):

| Model | Non-clarify correct | Clarify correct | Latency | Verdict |
|---|---|---|---|---|
| **anthropic/claude-3.5-haiku** | 5/5 | yes | 1.49s | **Primary teacher** |
| google/gemini-3.1-flash-lite | 4/5 | no (wait) | 0.81s | Secondary (clarify excluded) |
| hermes/openai-codex:gpt-5.4-mini | 5/5 | no (wait) | 6.49s | Secondary (clarify excluded, slow) |
| ibm-granite/granite-4.1-8b | 4/5 | no (speak) | 0.48s | Tertiary (clarify excluded) |

**Decision:** Use Claude 3.5 Haiku as the sole teacher. It is the only model that got all 6 scenarios correct after few-shot. No other model is reliable enough on clarify to justify blending.

**Fallback for scalability:** If we need more training data than Claude alone can provide, augment with Gemini Flash Lite and gpt-5.4-mini on the 5 non-clarify scenarios only. Never use them for clarify training signal.

## Action Space

Same 5 actions as Milestone 1:

| Action | Meaning |
|---|---|
| `speak` | Emit the queued utterance now |
| `wait` | Do nothing; stay in current state |
| `clarify` | Ask the user to repeat / confirm what they said |
| `repair` | Acknowledge collision, yield floor (e.g., "Sorry, go ahead.") |
| `yield` | Stop speaking immediately; user interrupted |

Action text content comes from the dialogue script (not generated by the distilled model in v1). The policy only chooses the action.

## Feature Representation

The distilled model receives the same perception frame as the current state machine:

```python
@dataclass
class PerceptionFrame:
    time_ms: float
    attribution: str          # "silence" | "user" | "both"
    silence_duration_ms: float
    vad_energy_db: float
    has_queued_utterance: bool
    state: str                # current FSM state: idle|listen|speak|repair|clarify
    user_speaking: bool
    agent_speaking: bool
    last_user_utterance: str
    last_agent_utterance: str
    history: list[dict]       # last N turns, speaker + text
```

For the distilled model, this gets flattened into a feature vector:
- `state` → one-hot (5 values)
- `attribution` → one-hot (3 values)
- `silence_duration_ms` → scalar, log-scaled
- `vad_energy_db` → scalar
- `has_queued_utterance` → boolean
- `user_speaking` → boolean
- `agent_speaking` → boolean
- Utterance text → not used in v1 (action selection is content-agnostic)

## Training Data Collection

### Seed: Deterministic Policy Transcripts

Run the deterministic simulator on the existing 9 scenario scripts (50 trials each, multiple seeds). For each tick where the policy makes a decision, record:

```python
{
    "features": PerceptionFrame(...),   # current perception
    "expert_action": "speak",            # deterministic decision
    "scenario": "speak_on_silence_baseline",
    "trial": 0,
    "tick": 12
}
```

This gives ~15,000–50,000 labeled decisions per scenario mix. It is the "safe but potentially narrow" signal.

### Teacher Augmentation

For a subset of the same perception frames (5,000–10,000), query Claude Haiku and record its action + explanation:

```python
{
    "features": PerceptionFrame(...),
    "teacher_action": "speak",           # Claude's decision
    "teacher_explanation": "The user is silent...",
    "agreement_with_deterministic": True # or False → interesting case
}
```

The disagreement cases are the most valuable for distillation: they show where the LLM sees something the deterministic rule misses.

### Hard-Negative Generation

Add edge cases that the deterministic policy handles correctly but a learned model might get wrong:

- **Short-pause ambiguity:** User pauses for 300ms mid-sentence. Correct: wait.
- **Post-response silence:** User just answered a question and went quiet. Correct: wait (not clarify).
- **Rapid turn-taking:** Back-and-forth with < 200ms gaps. Correct: speak / wait alternation.
- **Double collision:** Both speakers yield simultaneously. Correct: wait.

Generate 200–500 of these from scenario scripts with randomized timing.

### Dataset Split

| Set | Source | Size | Purpose |
|---|---|---|---|
| Train | Deterministic transcripts + teacher agreements | 80% | Learn the core policy |
| Val | Teacher disagreements + hard-negatives | 10% | Tune regularization |
| Test (in-distro) | Held-out deterministic trials | 5% | Verify baseline match |
| Test (OOD) | New scenario seeds + teacher-only labels | 5% | Measure generalization |

## Model Architecture

### Recommended: Small MLP + softmax classifier

```python
class DistilledSpeakingPolicy(nn.Module):
    def __init__(self):
        super().__init__()
        self.state_embed = nn.Embedding(5, 16)     # FSM state
        self.attr_embed = nn.Embedding(3, 8)         # attribution
        self.numeric = nn.Linear(4, 32)              # silence, vad, queued, speaking flags
        self.fc1 = nn.Linear(16 + 8 + 32, 64)
        self.fc2 = nn.Linear.Linear(64, 32)
        self.head = nn.Linear(32, 5)                 # 5 actions

    def forward(self, state, attr, numeric_feats):
        s = self.state_embed(state)
        a = self.attr_embed(attr)
        n = F.relu(self.numeric(numeric_feats))
        x = torch.cat([s, a, n], dim=-1)
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        return self.head(x)  # logits over 5 actions
```

- Parameters: ~5K–10K
- Inference: <1ms on CPU, <0.1ms on GPU
- Input: 53-dim embed + numeric vector
- Output: 5-dim action logits

### Why not an MLP from scratch

A pure MLP trained from simulated data will just reinvent the state machine. The point of distillation is to learn from the teacher's generalization ability, not to copy the rule.

So the training regime matters as much as the architecture:

1. Train on deterministic labels first (behavioral cloning)
2. Fine-tune on teacher labels where they disagree (distillation)
3. Add a KL-divergence loss against the teacher's softmax output where available

---

## Loss Function

```python
# Primary: cross-entropy on action labels
loss_ce = F.cross_entropy(logits, action_labels)

# Distillation: KL divergence from teacher logits (where available)
loss_kl = F.kl_div(
    F.log_softmax(logits / T, dim=-1),
    F.softmax(teacher_logits / T, dim=-1),
    reduction='batchmean'
)

# Total loss
loss = alpha * loss_ce + (1 - alpha) * loss_kl
```

Where:
- `T` = temperature (start at 2.0, reduce to 1.0)
- `alpha` = agreement weight (0.8 for deterministic labels, 0.2 for teacher-augmented)
- On teacher disagreement cases, flip to `alpha = 0.3` (trust teacher more)

## Safety Rails

The deterministic policy is not just a training source. It is also a runtime guard.

### Rule: Force deterministic action when safety condition applies

```python
class GuardedDistilledPolicy:
    def decide(self, frame):
        # Hard rules that must never be violated
        if frame.state == "repair" and frame.repair_utterance:
            return Action.REPAIR, frame.repair_utterance
        if frame.attribution == "both" and frame.state == "speak":
            return Action.YIELD, ""
        if not frame.has_queued_utterance and frame.state == "speak":
            return Action.WAIT, ""

        # Otherwise: use distilled model
        return self.model.predict(frame)
```

This means:
- **Yield on collision** is always correct (never learned, always enforced)
- **Repair emission** is always correct
- **Clarify** is the only action fully left to the distilled model (and the deterministic rule already handles it correctly, so this is about generalizations)

### Rationale

The benchmark shows that clarify is the weakest point for every LLM. It is also the least safety-critical action. Yield and repair have real-time conversational consequences. Clarify is about recovery. It is the right thing to leave to the learned model.

## Evaluation

### In-Simulator Metrics

Same as Milestone 1:

| Metric | Target | Deterministic baseline |
|---|---|---|
| Interruption rate | < 5% | 2.1% |
| Collision rate | < 5% | 6.6% |
| Response gap | 300–800ms | 496ms |
| Turn continuation | > 70% | 69.1% |
| Repair success (raw) | > 80% | 81% |
| Clarification success | > 90% | 100% |

### New: Generalization Metrics

| Metric | How to measure |
|---|---|
| OOD accuracy | On held-out scenario seeds the model never saw |
| Teacher agreement | % of decisions matching Claude on the same frames |
| Latency | Per-decision inference time (target: <5ms CPU) |
| Robustness to timing noise | Vary silence_duration ±200ms, measure action consistency |

### Protocol

For every distilled model checkpoint:
1. Run the full 50-trial deterministic scenario suite
2. Run the OOD scenario suite (new seeds)
3. Report scenario-conditioned metrics (not just aggregate)
4. Log all disagreement cases for manual inspection

## Implementation Plan

### Step 1: Infrastructure (Day 1–2)
- Add data collection mode to simulator (save perception frames + actions)
- Add teacher query mode (call Claude on logged frames, save outputs)
- Write data loader and train/val/test split logic

### Step 2: Training Data (Day 3–4)
- Run deterministic simulator across 9 scenarios × 50 trials × 3 seeds
- Query teacher on 10K random frames from the above
- Generate 500 hard-negative examples manually + via script randomization

### Step 3: Behavioral Cloning (Day 5–7)
- Train MLP on deterministic labels only
- Target: match deterministic accuracy on in-distro test set (>98%)
- Verify safety rails work independently of model

### Step 4: Distillation (Day 8–10)
- Fine-tune on teacher labels with KL loss
- Focus on disagreement cases and hard-negatives
- Monitor for catastrophic forgetting of deterministic behavior

### Step 5: Evaluation (Day 11)
- Run full scenario suite
- Compare to deterministic baseline
- Document all failure modes

### Step 6: Iteration or Pivot (Day 12+)
- If distilled model matches baseline → move to Milestone 3 (live validation)
- If distillation fails → analyze disagreement cases, refine teacher prompt or training mix, or keep deterministic policy as the long-term runtime

## Risks

1. **Simulation-to-reality gap:** The simulator is cleaner than real conversation. The distilled model may not generalize to live audio noise, variable user timing, or unexpected social behavior. Mitigation: add noise injection during training.

2. **Teacher blind spots:** If Claude is wrong on a class of scenarios, the distilled model will learn that error. Mitigation: always keep the deterministic guard rails active.

3. **Overfitting to scenario scripts:** The training data comes from scripted scenarios. The model may not handle truly novel conversational dynamics. Mitigation: add randomized scenario generation and augmentation.

4. **Distillation plateau:** A small MLP may not have enough capacity to capture the teacher's reasoning. Mitigation: try a slightly larger model (128→256 hidden) or switch to a small transformer if the MLP saturates.

---

## Success Criteria

Milestone 2 is complete when:
- [ ] Distilled model matches or exceeds deterministic baseline on all 6 in-simulator metrics
- [ ] Per-decision latency is < 5ms on CPU
- [ ] Clarify decision accuracy is > 90% (the key failure mode from M1)
- [ ] All safety rails (yield, repair) are enforced independently of the learned model
- [ ] Full scenario-conditioned evaluation report is written
